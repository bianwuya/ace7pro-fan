# 项目知识索引

本目录保存工程结构、工作流程与状态快照；不是代码实现，也不取代用户文档。先按任务读最少的入口，避免复制会过期的清单。

## 入口

| 需要了解 | 主文档 | 维护约定 |
|---|---|---|
| 自动化维护的核心边界 | [AGENTS](../AGENTS.md) | 任务开始先读；变更边界先取得明确需求 |
| 安装、使用、构建命令与用户可见行为 | [README](../README.md) | 面向使用者；不要在管理文档重复全部参数 |
| 硬件、系统、框架兼容矩阵及其验证证据 | [COMPATIBILITY](../COMPATIBILITY.md) | **唯一事实来源**；版本矩阵和兼容结论只在此维护 |
| 模块边界、组件职责与数据流 | [架构说明](ARCHITECTURE.md) | 设计变化时随代码职责同步，不复制兼容矩阵 |
| 开发、测试、构建、发布与 Git 约束 | [工作流程](WORKFLOW.md) | 命令约定与当前工具实现状态需区分 |
| 截止某时点的仓库和设备证据 | [状态快照](STATE.md) | 非实时状态；更新时写清证据时点与不确定性 |
| 稳定 ID、优先级、状态和验收标准 | [任务清单](../TASKS.md) | 任务完成后更新状态与可核验的验收证据 |
| 已交付包的精确来源、签名、哈希 | [0.3.0交付记录](../releases/0.3.0-compat/RECORD.md) | 同版本重构包必须用各自SHA256与提交号区分 |
| 有意维护的版本变化摘要 | [变更记录](../CHANGELOG.md) | 不猜日期；详细兼容事实仍回到 COMPATIBILITY |

## 维护规则

- 一类事实只维护一个主入口；索引只负责导航。
- “能编译/合成测试通过”“目标设备已加载”“真实 ROM 或物理效果验收通过”是不同层级，不能互相代替。
- 项目状态按证据记录，不把已安装包、旧进程日志或版本字符串当成当前 Hook 已加载的证明。
- 文档变更也要检查相对链接与相邻文档的一致性；不为文档任务自动构建、安装或重启设备。
