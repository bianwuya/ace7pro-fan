# 0.7.2-rpm-events

## 新增

- 从原厂既有 FG 测速事件被动读取 `FAN_RPM`，概览增加「风扇实测转速 · 档位保持值」，趋势增加对应 RPM 曲线。
- 按用户补充要求，同一驱动有效档位保持首次有效实测，到有效档位变化后等待新测量。显示实测时刻与保持语义，不伪称连续实时速度。
- JSON 增加可选 `fanRpm` 对象；CSV 原有列和顺序保留，在末尾追加 `fanRpm_*`。

## 修复

- 传感器曲线和充电模式直接展开、不再折叠；传感器曲线放在有效档位曲线上方。
- 旧 `/sys/class/leds/fan/rpm` 保持弃用，不用 speed/duty、目标 RPM 或档位换算实测速度。
- 换档、停用、故障、未知档位、调试覆盖和时钟跳变使保持值失效；跨请求在途证据不被接受。正请求未改变有效档位时不清除首次保持值；换档后至少等待 2 秒稳定窗口再采纳事件。

## 验证与限制

- App `0.7.2-rpm-events` / versionCode 19，Hook `0.6.3-rpm-events`；沿用已有签名与配置、历史，不安装、不重启原厂服务、不改变 LSPosed 或原厂设置，不上传发布。
- 纯 Java 回归含 39 项测速检查和既有日用、充电、锁屏交还、采样与前端历史检查。完整编译、签名及包身份结果见 [状态快照](../../knowledge/STATE.md)。
- 找到的是驱动测速结束的 FG 事件，不是已经验证稳定的新 sysfs 节点。本轮自然观察时风扇未使能，尚无本版 Hook 接收的运行测速；不能声称稳定性、全档测速或物理准确度已验收。事件接口缺失、原厂自检未监听、无有效事件时显示「—」。
- 当前驱动状态仍须新鲜，保持值并非跨重启缓存；原厂事件没有窗口时间戳或硬件代次标识，保守屏障不等于物理归属证明。需要正常重载 Hook 后在自然运行中验收。详见 [测速证据与设计](../../knowledge/FAN-RPM.md)。
