# 0.7.4-rpm-hold

## 新增

- 概览与趋势增加风扇 FG 实测转速的档位保持值：同一有效档位首次取得有效测量后持续显示，直到有效档位变化再等待新测量。明确显示测量时间和保持语义，不冒充连续实时测速。
- CSV 在既有列之后追加 `fanRpm_*`，历史 JSON 追加可选对象；旧记录、设置和权限边界保持兼容。

## 修复

- 传感器曲线和充电模式直接展示，不再折叠；传感器曲线位于有效档位曲线之上。
- 基于云端 `fix/fan-0.7.3-hysteresis` 的 `691bbe4` 增量整合；保留从零档启停的普通自动目标确认、1°C 回差、连续 30 秒降温确认、异常热状态交还、充电策略与 GitHub 适配入口。
- 旧不稳定 `rpm` 节点不恢复，不使用 duty/speed 或目标 RPM 估算。停转、换档、异常、未知反馈和调试覆盖时不沿用旧值；请求变化但有效档位未变时不替换首次保持值。

## 验证与限制

- App versionCode 21，Hook `0.6.5-rpm-hold`；沿用既有签名。覆盖安装不卸载、不清数据、不改变设置；原厂服务与整机不由本次操作重启，用户自行正常重启后实测。
- 合并回归包含云端原样保留的 341 项日用策略检查、39 项测速检查及充电、锁屏交还、采样、接口、报告、配置和前端历史回归。完整构建、安装及 GitHub 主分支同步结果见 [状态快照](../../knowledge/STATE.md)。
- 数据来源是驱动健康检查结束的 `FAN_RPM` FG 事件，不是新发现的稳定 sysfs 节点；尚未验证本版运行事件连续性和物理准确度。原厂未监听/未发送或接口不可用时显示未知，不填假零，不新增自检或监听生命周期。
- `FanRpm` 的代次屏障、前后驱动状态核对及换档后稳定窗口为保守软件检查；事件不提供硬件测量时刻，不能代替真机验证。详见 [测速证据](../../knowledge/FAN-RPM.md)。
