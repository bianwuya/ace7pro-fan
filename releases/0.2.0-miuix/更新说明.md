- 同签名覆盖安装，配置与历史数据库保留。

## 这一版做了什么

1. **前端重做**（参考 Miuix 视觉语言，自绘 Java 视图，未引入 Compose 依赖）
   - 概览 / 趋势 / 设置三页 + 底部导航，替换原来的按钮墙。
   - 24dp 圆角实色卡片、大标题、克制的蓝色强调、深浅双主题。
   - 自绘开关、分段控件、主题化弹窗；深色界面不再出现黑字下拉框。
   - 概览显示当前阶段、增强开关、电池温度、驱动有效档位、辅助温度与迷你趋势。
   - 趋势把温度与档位拆成两张独立卡：图例在绘图区外，刻度取整，档位 0—20 固定刻度，可展开诊断线。

2. **完整移除转速（RPM）**
   - 不再读取 `/sys/class/leds/fan/rpm` 与 `speed`。
   - 图表、卡片、诊断、预览日志都不再出现转速。
   - CSV 新表头去掉 `rpm` 列，其余列保留；历史 JSON 里的旧 rpm 不再导出，数据库不做破坏性重写。
   - 档位仍表示控制请求，不被换算成“转速”。

3. **状态与版本显示更诚实**
   - 顶部胶囊区分“已注入 / 待重载 / 未注入 / 只读预览”。
   - 旧版 Hook 没有版本字段时显示“待重载”，不会把旧代码误报成已更新。

4. **修复**
   - 启动崩溃：`Window.getInsetsController()` 在 `setContentView` 之前调用会空指针。
   - 温度图纵轴刻度不均匀（33/37/40/44）改为取整步进（33/36/39/42）。
   - 无数据的序列图例自动置灰，避免误以为“线丢了”。
   - 无导航栏内边距的环境下底部文字贴边。

## 没有改动

- 控制策略、温度曲线阈值、降档迟滞、Hook 点、原厂保护判断全部保持原样。
- 不写 sysfs、不伪装温度、不改充电与关机保护。

## 安装后请这样确认

1. 打开 App，看顶部是否显示“已注入”，否则重启一次让目标服务加载新 Hook。
2. 概览页标题下应显示“当前阶段”；息屏有线充电时才会出现“息屏增强”。
3. 趋势页切换 15 分钟 / 30 分钟 / 本次充电，温度与档位两张卡都应正常绘制。
4. 设置页切换深色 / 浅色，界面应整体重建且不崩溃。
5. 导出 CSV 后检查表头：不应再有 `rpm` 列。

## 未验证

- 提示“待重载”是预期状态：本次安装的 Hook 需要目标进程重新加载后才会生效；UI 改动不需要重启。
