# ACE 7 系列风扇助手 0.9.1-kernel-rpm

OnePlus ACE 7 系列的 LSPosed / 传统 Xposed 模块与本地观测 App。作用域仅 `com.oplus.exsystemservice`。无网络权限。0.8.0 在已核验的原厂接口上独立计算目标并直接写风扇 level/state；保留原厂下游保护及驱动查表，不改温控节点。

## 0.9.1：内核日用升档与实测转速

统一KSU包包含同签名App、完整驱动和早期加载器。修复独立日用路径固定最低档的问题：用用户融合温度驱动本机原厂普通阶梯，保留启停门控、最低档、回差和normal斜坡；Root直接被动接收真实FG事件并回传同档位保持值。RPM已在本机正式Provider实收验证，新日用驱动已安装至下一启动，实际升档仍待用户重启后验收。详见 [本版说明](releases/0.9.1-kernel-rpm/NOTES.md) 与 [当前检查点](knowledge/KERNEL-CURRENT.md)。

## 历史0.8.1：节点权限适配

- 本机system_app不能直接写风扇sysfs时，软件目标改走原厂已授权的fan-only节点通道（IOplusMisc的401/403），再以原始sysfs读回确认。仍不依赖horae作目标决策，不改节点权限或SELinux，不增加App Root权限。诊断明确区分direct-sysfs与software-oem-node-bridge。
- 实机FG事件已收到，但服务身份不能读取dbg_rpm。既有Root守护增加该参数的只读转报，按本次boot及15秒新鲜度校验；过期/缺测/调试覆盖仍拒绝显示，不把转报当RPM来源。
- 停转时允许原厂启动初值level0；正档仍严格限1..20。原厂保护、原升降斜坡、全部设置和不在充电时恢复伪装的条件不变。

## 0.8.0：独立控制

- 保留日用融合阈值、权重、最低档和充电曲线；软件每5秒推进目标，不依赖 horae 的风扇更新。充电直控覆盖亮屏场景，旧接口回退仍保留原策略。
- 使用原厂普通档升降斜坡（0.2/0.1档每秒、整数时间截断）和驱动原有RPM查表。只写 level/state 的必要边沿，不反复抬回驱动降额；保留原厂下游场景、故障、手柄、降噪与使能。
- 修正测速调试参数路径；首页仅显示转速与简短状态。新 `nodeControl` 遥测区分直控可用、请求、写回读和错误，不用档位估算RPM。
- `modules/horae_fan_spoof` 提供仅在已拔线且明确放电时恢复29.5°C的补充守护；插电、充电或供电未知时不写温度状态，不启停horae，不改充电模块。
- 运行状态与验收边界见 [状态快照](knowledge/STATE.md)。覆盖安装不代表新Hook已经加载。

## 0.7.4：档位实测保持与直显曲线

- 趋势的传感器曲线直接展示，并位于有效档位曲线上方；设置的充电模式及原有开关直接展示，不再折叠。
- 概览与趋势新增「风扇实测转速 · 档位保持值」：只从原厂已有测速回调被动读取 `FAN_RPM`，同有效档位保留首次有效实测，换档后等待新档位实测；停用、故障、档位未知或当前遥测过期时不显示旧值。测量时间与保持语义明确标注，不冒充连续实时转速。
- 原不稳定的 `/sys/class/leds/fan/rpm` 继续弃用，不读取 duty/speed 或用目标 RPM、档位估算。此次找到的是驱动 FG 测速事件，不是已经证明稳定的新 sysfs 节点。接口缺失、原厂没有发送事件、无法排除调试覆盖时显示「—」。
- JSON 仅追加可选 `fanRpm` 对象，CSV 在既有列之后追加 `fanRpm_*`；配置表、旧样本和 Provider UID 边界不变。Hook 更新为 `0.6.5-rpm-hold`，需要按正常流程重载后才可能接收到新事件，不自动重启服务。
- 验证与实机限制见 [测速证据与设计](knowledge/FAN-RPM.md) 和 [状态快照](knowledge/STATE.md)。

## 0.7.3：日用防频繁启停与适配入口

- 修改设置时可选「只保存参数」或「保存并开启日用增强」；已有开关、温度、档位和权重不会因覆盖安装改变。
- 普通自动场景确认后，融合温度高于设定值可由 0 档起转；起转后，只有新鲜连续样本确认温度比设定值低至少 1°C 并保持 30 秒，才请求停转。期间回温会清零计时。原厂保护、特殊场景和充电逻辑优先，不由 App 直接驱动风扇。
- 概览右上角「数据与诊断 → GitHub 源码与适配」打开项目仓库，可查看源码和 [兼容说明](COMPATIBILITY.md)。该入口不需要 App 网络权限，也不上传本机报告。
- 概览标出实际参与融合的通道，区分温度目标、原厂控制请求与驱动反馈。权重为 0 的传感器不参与融合，但仍用于异常高温检查。

## 0.7.0：Miuix 前端

- 概览把运行状态收为一行小字，首屏显示融合温度、驱动有效档位，以及电池、主板、风扇周边和充电 MOS 四路读数。没有遥测时显示“—”；只读计算会标明“预览”。
- 设置中可独立开关日用增强，编辑介入温度、最低增强档位、四路权重。权重编辑器可预览融合结果和本次实际参与占比，保存回执不等于 Hook 已读取或风扇已执行。
- 趋势默认为融合温度、历史日用介入温度和有效档位，原始传感器曲线直接展示，诊断按需进入。支持跟随系统／浅色／深色，测速以明确标记的实测保持值独立显示。

## 运行接口与失败报告

- 适配范围为 ACE 7 系列：读取型号及原厂市场名称；同系列变体不再强求 PMS110/OP64F1L1 完全一致。
- 去掉 APK/DEX/语义指纹启动条件，直接解析实际编排器、候选、当前策略与档位上限并记录实读结果；不要求 11 个参考方法齐全。
- 场景满足即允许候选应用；把候选、同轮控制请求、原厂状态确认分别记录。未触发是等待，限档是原厂结果，不预先判不能用。
- 健康方法改名/歧义、确认字段缺失与辅助遥测失败独立报告；不再跨环节累计 5 次异常全局熔断。
- 失败报告包含具体环节、实际成员、异常、时间和计数。先把报告发给开发者，再按不足之处补证据；不要求先提供 APK 才能尝试。

## 充电模式（原行为保留）

- 充电增强只在有线充电中、息屏、原厂自动模式及原厂开关允许时按电池温度增强。
- 先前息屏增强真正生效后，亮屏仍锁屏可延续；真正解锁后最多 2 秒交还原厂。不扩大充电模式的亮屏、无线、手动等范围。
- 仍在候选层增强，后续噪声、使能、手柄、控制器、底层保护保留。口袋、通话、故障等场景不会因“扩大兼容”强行加入白名单。
- 沿用 0.6.0 充电策略及 `start_temp`：电池温度，默认 33°C、6 档起、每度约 2 档、上限 20，撤掉增强需低于门槛 1°C 持续 30 秒。这不是安全温度边界。
- 档位是控制请求，不等于物理转速；驱动可能降额。旧 rpm 节点和 duty/speed 读取保持弃用；仅被动接收驱动 FG 事件，不用档位换算冒充转速。

## 日用模式

日用只在未接电、明确由电池供电且原厂允许时生效，默认关闭，不共用充电开关和配置。确认普通自动目标且热状态正常时，融合温度 `≤` 设定值请求停转，`>` 设定值请求起转并以设定档为下限。未识别普通自动路径的 ROM 仍只支持原有正档增强。见 [日用配置与遥测契约](knowledge/DAILY-FAN.md)。

## 别人的机器失败时怎么反馈

设置 → 数据与诊断 → 模块与设备兼容报告（或概览右上角 ⋯）→ 复制、分享或保存完整报告，连同实际现象和发生时间发给开发者。

报告记录 ACE 7 系列识别、原厂服务版本、实际接口清单、各环节调用与失败、最近异常和已恢复的失败历史。无账号/位置/通讯录，App 无网络权限，不自动发送。

观察顺序：接口接入 → 场景与上限实读 → 候选应用 → 同轮控制完成 → 原厂状态确认。未触发/未取得的记录表示未知，不冒充失败或物理实测成功。

## 界面与数据

概览/趋势/设置使用真实 Compose Miuix 组件。界面读写配置、查看历史，不直接控制风扇。缺测断线，当次遥测不可读显示“—”。

继承 0.2.1 的采样降耗：增强窗口 5 秒、具备条件未增强 10 秒、不可接管 30 秒；插拔电、息屏、解锁、电池事件补采。状态/档位变化或温度变化 ≥0.2°C 时写入，否则至少每 20 秒一条。新鲜度随采样周期调整。历史上限 10000 点/7天，界面最多4000点，曲线断点阈值60秒。CSV 不含转速列。

## 安装与使用

1. 安装 APK；框架必须先支持你的 Android，只有独立 Manager APK 不会激活框架。
2. 在 LSPosed 启用模块，只勾选 `com.oplus.exsystemservice`。不要勾选系统框架/system_server。
3. 正常重启。已运行的原厂服务不会因覆盖安装立刻加载新 Hook；App 显示“待重载”时请重启再看。
4. 检查“版本兼容性”：运行 Hook 为 `0.6.2-daily-feedback` 后，查看实际接口接入、候选应用、控制反馈和失败环节。注入与物理效果分别判断。

功能验收由用户手动操作；本包不自动重启、杀掉原厂服务、改 LSPosed/安全设置，也不请求 Root 作为工作前提。回退可关闭增强，或在 LSPosed 禁用后重启；不自动卸载/清数据。

## 构建与测试

Linux ARM64 可用 JDK 25、Gradle 9.7.1、AGP 9.5.1、Kotlin Compose 2.4.21、SDK 37.2 构建，APK 保持 min28/target35。真实 Miuix UI/Preference 为 0.9.5-beta01；Xposed API82 仅 compileOnly。准备命令和 AAPT2/签名预检见 [工作流程](knowledge/WORKFLOW.md)。

```sh
sh tests/run.sh
sh build.sh              # 原签名本地构建
sh build.sh --unsigned   # 无密钥检查包，不可安装
```

产物：`build/ACE7pro_Fan_0.7.3-fusion-hysteresis.apk`。纯 Java 测试涵盖曲线、锁屏衔接、采样、接口直接调用与部分能力缺失、配置就绪恢复、逐环节证据及报告。默认测试不再运行历史指纹对比。

已做离线测试和构建校验，不等于已做其他 ROM/框架或物理风扇效果实测。详细边界见兼容文档。
