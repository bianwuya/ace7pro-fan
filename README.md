# ACE 7 Pro 风扇助手 0.9.3-manual-handoff

为一加 **ACE 7 Pro** 提供日用风扇策略、独立充电策略、温度趋势与真实转速观测。统一 KernelSU ZIP 包含配套 App、风扇驱动和早期加载器；App 无网络权限，数据保存在本机。

## 功能

- **日用自动控制**：电池供电、原厂智能模式且安全条件允许时，按电池、主板、风扇周边、充电 MOS 四路温度融合。可设置介入温度、最低档和权重；采用普通升降档斜坡及停转回差，减少频繁启停。
- **独立充电策略**：保留单独开关和温度参数，与日用设置分离；有线充电时按既有充电曲线工作。
- **原厂手动和游戏**：静音、极限及游戏场景交还原厂处理。切手动后，内核只继续观测，不计算或强写手动目标。
- **温度与历史**：概览显示四路传感器、融合温度和实际有效档位；趋势保留温度、档位、转速历史，支持 CSV 导出。缺测显示“—”并保留曲线缺口，不补造数据。
- **真实转速**：被动接收原驱动 FG 测速事件，同档位保持有效实测值；换档等待新测量，停机或故障清除旧值。不以档位或目标表估算 RPM。
- **安全与诊断**：保留原厂故障、降额、缺失检测、使能、手柄、降噪及底层保护。诊断区分设置已保存、控制已就绪与真实硬件结果。

## 实现方案

```text
App 设置 → UID 校验的本地 Provider → Root 设置/安全桥 → 内核策略与原驱动
                                         ↓                ↓
                                  原厂交还确认       温度/状态/FG
                                         ↓                ↓
                                  原厂线程重新决策 ← 本地统计与展示
```

温度采样、融合、自动策略和正常斜坡在内核执行。Root 桥仅传递配置、安全条件和有界租约，回传内核结果；App 负责设置和显示，不在界面或 Java 中轮询温度来控制风扇。

控制权限与观测分离：离开自动场景后，先撤销控制权，四路温度仍由内核采样。手动交还使用精确配置版本的内核确认，再通过只允许 Root 写入的短时凭据通知原厂线程；仅使“同档已成功”的缓存失效，重新走完整原厂决策，不直接调用档位/使能接口，不绕过故障保护。

既有 Horae 风扇温度解耦按已验证原件安全派生；未知二进制不套用固定偏移。29.5°C 状态恢复仅限未插电且明确放电，不启停 Horae、不更改独立充电模块。

## 安装与兼容

1. 使用 KernelSU 安装统一 ZIP，配套 App 覆盖升级并保留原设置及历史。
2. 在已支持当前系统的 LSPosed 中启用 App，仅勾选 `com.oplus.exsystemservice`。
3. 自行正常重启，使新驱动与原厂进程内的交还桥一起生效。覆盖安装不代表新内核代码已经运行。
4. 在 App 诊断中核对实际运行后端，再测试智能直接切极限、手动互切和返回智能。

产品识别仅限 ACE 7 Pro（已知型号 PMS110 或完整市场名称），安装器不再附加项目号和内核版本字符串白名单。**这不等于任意内核通用**：驱动仍依赖 ABI、符号 CRC、CFI 与布局，当前早期加载器保留已验证内核的安全绑定；未经验证不强行替换驱动。完整边界见 [兼容说明](COMPATIBILITY.md)。

## 本版修复与验证

- 补上自动控制交还手动后的原厂重新决策，处理首次请求被旧所有权挡住、同档缓存不重发的路径。
- 解耦只读遥测与控制租约，修复手动/游戏等非接管状态下四温度与融合曲线中断。
- 保留全部历史数据、独立充电设置和原厂保护；不自动重启或强杀系统服务。

2026-11-28 已在本机重启后验证智能直切极限、手动互切和手动四温度/融合历史。连续原厂运行仍观察到过 `BLOCKED`，随后自行恢复，根因尚未确认；未绕过保护，不作长时稳定承诺。实测范围与限制见 [本版记录](releases/0.9.3-manual-handoff/NOTES.md)。
